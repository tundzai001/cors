# Hard-coded shared MQTT credentials can expose the fleet control plane

## Executive Summary

Two deployed field-agent implementations contain the same hard-coded MQTT
username and password and use those values as runtime fallbacks. The agents do
not treat the broker identity as a low-privilege telemetry credential: one
agent consumes station command topics, while the Geotek relay subscribes to
command and status wildcards covering every device. Messages delivered through
those subscriptions reach license deployment, service reconfiguration, raw
receiver command execution, device reset, serial changes, and stream control.

Anyone who can read the source, an installation package, a copied field-agent
deployment, or retained source history can recover the shared credential. If
the credential remains active and the broker ACL grants the rights requested by
these clients, source disclosure becomes a path into the fleet control plane
without a dashboard account or prior device compromise. The precise blast
radius depends on server-side ACLs, but publishing one reusable secret in two
deployed clients defeats the secrecy assumption on which broker authentication
depends.

I reviewed revision
`13546e7b992aefb3237e9e56d5e6c70c529db3ff` and worktree snapshot
`codex-security-snapshot/v1:sha256:32c72b8edad7b25495bf771955ed951c46bc67644dec918876744c2d10a6fad0`
directly. I validated the credential fallback, MQTT subscriptions, and command
dispatch statically and ran only the included offline inventory probe. I did
not authenticate to the configured broker, contact a station, caster, receiver,
or production service, or test whether the credential is still accepted.
There is no known fixed revision in the material reviewed.

This issue is critical when the shared identity retains fleet-wide publish or
subscribe rights, because compromise then provides reliable control or
impersonation across many deployed stations. If the credential has already
been revoked or its ACL is strictly read-only and narrowly scoped, current
operational impact is lower, but the shipped-secret defect still requires
rotation and architectural correction.

## Background

The project has two Python field-agent paths that connect GNSS stations and
relay hardware to an MQTT control plane:

- `geodetic/agent_universal.py` runs a per-station agent. It subscribes to
  command topics derived from the machine serial and dispatches received JSON
  to `process_command()`.
- `geodetic/geotek_daithanh_aitogy.py` runs a multi-device Geotek relay. It
  subscribes to wildcard command and status topics and selects a worker from
  the serial carried by the topic or payload.

Broker authentication is the first security boundary in both paths. After a
message has passed that boundary, neither client verifies a separate message
signature or dashboard identity. The normal invariant therefore has to be:

> A credential embedded in a field device must be unique to that device, must
> be provisioned outside distributable source, and must be authorized only for
> the device's own minimum set of topics.

The vulnerable revision breaks all three parts of that invariant. The same
literal is recoverable from source, it is reused by two agent families, and one
consumer requests cross-device wildcard subscriptions.

The universal agent declares the broker defaults at module scope. Values are
masked here and throughout this report.

```python
# geodetic/agent_universal.py:317-328
DEFAULT_MQTT_BROKER = "<configured-broker>"
DEFAULT_MQTT_PORT = 1883
DEFAULT_MQTT_USERNAME = "<MASKED-SHARED-USERNAME>"
DEFAULT_MQTT_PASSWORD = "<MASKED-SHARED-PASSWORD>"

MQTT_BROKER = DEFAULT_MQTT_BROKER
MQTT_PORT = DEFAULT_MQTT_PORT
MQTT_USERNAME = DEFAULT_MQTT_USERNAME
MQTT_PASSWORD = DEFAULT_MQTT_PASSWORD
```

An installation can supply an `mqtt` configuration object, but missing or
empty fields silently return to the embedded identity:

```python
# geodetic/agent_universal.py:536-559
def _get_mqtt_runtime_config(agent=None) -> dict:
    cfg = {}
    if agent is not None and isinstance(getattr(agent, "config", None), dict):
        cfg = agent.config.get("mqtt") or agent.config.get("mqtt_config") or {}
        if not isinstance(cfg, dict):
            cfg = {}

    return {
        "broker": str(broker or BACKEND_HOST).strip(),
        "port": port,
        "username": cfg.get("username") or cfg.get("user") or DEFAULT_MQTT_USERNAME,
        "password": cfg.get("password") or cfg.get("pass") or DEFAULT_MQTT_PASSWORD,
    }
```

This fallback is important: deleting a local setting does not fail closed. It
reactivates a credential that is present in every copy of the program.

## Vulnerability Details

We can follow the shared value through each agent independently.

### Universal agent: source literal to station command dispatcher

`setup_mqtt_client()` resolves the configuration, supplies the username and
password to Paho MQTT, and subscribes to three serial-specific command topic
variants. Its message callback parses attacker-supplied JSON and schedules
`process_command()` without a second cryptographic authorization check.

```python
# geodetic/agent_universal.py:5181-5205, 5221-5235, 5251-5267
def setup_mqtt_client(loop, agent, gnss_reader):
    mqtt_cfg = _get_mqtt_runtime_config(agent)
    client = mqtt.Client(client_id=f"agent-{MACHINE_SERIAL}-{os.getpid()}")

    command_topics = [
        f"pi/devices/{MACHINE_SERIAL}/command",
        f"pi/devices/{MACHINE_SERIAL}/commands",
        f"pi/device/{MACHINE_SERIAL}/command",
    ]

    def on_connect(c, userdata, flags, rc, properties=None):
        if rc == 0:
            for topic in command_topics:
                c.subscribe(topic, qos=1)

    def on_message(c, userdata, msg):
        data = json.loads(msg.payload.decode())
        asyncio.run_coroutine_threadsafe(
            process_command("mqtt", data, userdata["agent"],
                            userdata["gnss_reader"], c),
            loop,
        )

    client.username_pw_set(mqtt_cfg["username"], mqtt_cfg["password"])
    client.connect_async(mqtt_cfg["broker"], mqtt_cfg["port"], 30)
```

The command validator checks command names and payload shapes, not who
authorized the message. Once the broker delivers a message, we can carry it
into operations with material local effects:

```python
# geodetic/agent_universal.py:4749-4768, 4840-4849, 4968-5012
known_commands = {
    "LOCK_DEVICE", "UNLOCK_DEVICE", "PROVISION_DEVICE", "DEPLOY_LICENSE",

    "REBOOT_DEVICE",
}

async def process_command(source, data, agent, gnss_reader, mqtt_client):
    command = data.get("command")
    payload = data.get("payload", {})
    is_valid, validation_error = _validate_command_payload(
        command, payload, data, agent, gnss_reader
    )
    # ...
    if command == "DEPLOY_LICENSE":
        with open(LICENSE_PATH, "w") as f:
            f.write(payload["license_key"])
    # ...
    elif command == "EXECUTE_RAW_COMMANDS":
        # ...
        decoded_cmd = base64.b64decode(cmd_b64)

```

Other branches restart the agent, change stream state, replace durable service
configuration, and remove configuration and license files. The decisive point
is not that the MQTT credential itself executes a command. It is that the
shared credential is the only remote identity check visible before broker
messages enter this privileged dispatcher.

### Geotek relay: the same secret reaches cross-device wildcards

The Geotek implementation contains the same password in two fallback shapes.
When no configuration file exists, it writes the embedded MQTT object into
memory. Later, `MQTT_PASS` also falls back to the same literal. The
`config_value()` helper accepts a tuple of environment-variable names but does
not read the environment in the reviewed revision; it checks only the loaded
section and then returns `default`.

```python
# geodetic/geotek_daithanh_aitogy.py:78-94, 339-351
def load(self):
    if os.path.exists(self.config_path):
        # load JSON configuration
        ...
    else:
        self.data = {
            "mqtt": {
                "broker": "<configured-broker>",
                "port": 1883,
                "user": "<MASKED-SHARED-USERNAME>",
                "password": "<MASKED-SHARED-PASSWORD>",
            },
            # ...
        }

def config_value(section, key, env_keys, default):
    section_data = config_mgr.data.get(section, {})
    value = section_data.get(key)
    if value is not None and str(value).strip() != "":
        return value
    return default

MQTT_USER = config_value("mqtt", "user", ("MQTT_USERNAME",),
                         "<MASKED-SHARED-USERNAME>")
MQTT_PASS = config_value("mqtt", "password", ("MQTT_PASSWORD",),
                         "<MASKED-SHARED-PASSWORD>")
```

The relay then authenticates with that identity and requests wildcard access:

```python
# geodetic/geotek_daithanh_aitogy.py:3233-3249
def setup_mqtt(worker_map):
    client = mqtt.Client(client_id=f"relay-{int(time.time())}")
    if MQTT_USER and MQTT_PASS:
        client.username_pw_set(MQTT_USER, MQTT_PASS)

    def on_connect(c, userdata, flags, rc, properties=None):
        if rc == 0:
            c.subscribe("pi/devices/+/command", qos=1)
            c.subscribe("pi/devices/+/commands", qos=1)
            c.subscribe("pi/device/+/command", qos=1)
            c.subscribe("pi/devices/+/status", qos=0)
```

The callback derives `serial` from the topic and routes commands into the
matching worker. We then reach operations such as remote command execution,
durable service configuration, license writes, worker restarts, serial
changes, and stream activation (`geodetic/geotek_daithanh_aitogy.py:3275-3410`).
For example, `EXECUTE_RAW_COMMANDS` starts `worker.execute_commands()` in a
background thread, and `DEPLOY_LICENSE` writes a new license for the selected
serial.

This gives us a complete source-level proof:

1. The password is a literal in distributable source and is duplicated across
   two deployed agent implementations.
2. Missing local configuration selects that literal rather than stopping.
3. Both clients authenticate to MQTT with the recovered value.
4. The clients consume privileged command topics; one requests cross-device
   wildcards.
5. Delivered messages reach high-impact device and receiver actions without a
   separate message-level authorization mechanism.

## Exploitability Analysis

The strongest route depends on broker state that source review cannot prove.
If the account remains active and may publish to the command filters consumed
by the agents, a source reader can impersonate the control plane. We would
need a target serial and a command accepted by the relevant implementation,
but no dashboard session is required at the agent boundary. On the universal
agent, delivery to a station-specific topic reaches `process_command()`; on
the Geotek relay, the topic selects a worker from a process that already
subscribes across devices. The available actions include raw receiver writes,
durable configuration replacement, license replacement, restart/reset, and
stream control. That is the fleet-control primitive behind the critical
rating.

A second route is confidentiality rather than command execution. The Geotek
client asks to subscribe to `pi/devices/+/status`, and status messages may be
retained. If the shared principal has matching subscribe rights, another
client using the recovered identity may receive cross-device operational data.
This route is less dependent on publish permissions, but its exact data set and
sensitivity remain broker- and deployment-specific.

There are meaningful constraints:

- A broker-side rotation that revoked the literal before disclosure prevents
  current authentication with it.
- MQTT ACLs may distinguish publish from subscribe and may be narrower than the
  filters requested by the clients. A subscription in source proves intended
  consumption, not that the broker grants every requested filter.
- Network isolation may make the broker unreachable from an arbitrary source
  reader. It does not restore secrecy for insiders, copied installations, or
  any actor who reaches the protected network.
- The universal client uses a serial- and process-specific client ID, and the
  relay uses a time-derived client ID. Reusing the username alone therefore
  does not provide a deterministic same-client-ID disconnect primitive.
- Payload validation rejects unknown command names and malformed shapes. It
  reduces accidental misuse, but it is not authorization: a correctly shaped
  message delivered through the broker proceeds to the privileged branch.

We should also avoid overstating the wildcard evidence. The relay's wildcard
subscriptions strongly imply a shared cross-device service identity, but they
do not by themselves prove that the same account can publish fleet commands.
That is why an authorized broker-side ACL review remains necessary for final
blast-radius measurement. I deliberately did not perform that review with the
exposed credential because the testing authorization was static and local
only.

## Proof of Concept

The accompanying PoC is an offline source-inventory probe. It never imports an
MQTT client, opens a socket, resolves the configured host, or prints credential
material. It parses the two Python files with the standard-library AST, finds
literal MQTT password assignments and MQTT password defaults, and reports only
masked locations and whether the same literal occurs in more than one file.

Place the report directory beside a checkout named `cors`, then run:

```sh
cd geo-001/poc
python inventory_probe.py --repo ../../cors \
  --revision 13546e7b992aefb3237e9e56d5e6c70c529db3ff
```

Representative output from the reviewed revision is:

```text
[!] hard-coded MQTT password/default: geodetic/agent_universal.py:322 value=<MASKED>
[!] hard-coded MQTT password/default: geodetic/geotek_daithanh_aitogy.py:93 value=<MASKED>
[!] hard-coded MQTT password/default: geodetic/geotek_daithanh_aitogy.py:351 value=<MASKED>
[!] one MQTT password literal repeats 3 times across 2 files
[!] vulnerable credential pattern present (3 occurrences)
```

The probe exits with status 2 when it finds the vulnerable pattern and status 0
when neither target contains a literal MQTT password/default. It changes no
files and requires no cleanup. `poc/README.md` contains the complete usage and
safety notes.

This PoC demonstrates the source-disclosure primitive and secret reuse. It
does not demonstrate broker acceptance, topic authorization, command delivery,
or station impact, because testing any of those would contact a live service
outside the authorization boundary.

## Remediation

The remediation invariant is straightforward: no distributable code path may
contain or silently select a reusable broker secret, and every deployed device
must receive a unique least-privilege identity through a protected provisioning
channel. Missing credentials must stop the client before it attempts a
connection.

A minimal source-level correction removes every literal default and makes
credential loading fail closed. The Geotek helper should also honor the
environment keys its interface already accepts:

```python
def required_config_value(section, key, env_keys):
    for env_key in env_keys:
        value = os.getenv(env_key)
        if value and value.strip():
            return value.strip()

    value = config_mgr.data.get(section, {}).get(key)
    if value is not None and str(value).strip():
        return str(value).strip()

    raise RuntimeError(f"required setting is missing: {section}.{key}")


MQTT_USER = required_config_value("mqtt", "user", ("MQTT_USERNAME",))
MQTT_PASS = required_config_value("mqtt", "password", ("MQTT_PASSWORD",))
```

The universal agent should apply the same rule in
`_get_mqtt_runtime_config()` and remove `DEFAULT_MQTT_USERNAME` and
`DEFAULT_MQTT_PASSWORD` entirely. An environment variable can be a useful
transition mechanism, but a protected per-device configuration or OS secret
store is preferable because environment values are often exposed through
service managers, diagnostics, or process inspection.

The source patch is only the beginning. The exposed value must be treated as
compromised even if the broker currently rejects it:

1. Revoke and rotate the shared principal immediately; do not preserve it as a
   compatibility fallback.
2. Provision a cryptographically random credential or client certificate for
   each device. Record ownership and rotation state server-side.
3. Restrict each field-agent principal to its own serial's minimum publish and
   subscribe filters. Reserve cross-device wildcards for a separately managed
   control-plane service identity that is never shipped to stations.
4. Review retained messages and broker audit logs for use of the exposed
   identity, unexpected client IDs, and cross-device access.
5. Add message-level authenticity and replay protection for high-impact
   commands so a broker credential alone is not the final authorization gate.
6. Remove the secret from distributed packages and reachable source history
   where practical. Rotation remains mandatory because history rewriting does
   not revoke copied values.

Regression coverage should enforce the restored invariant:

- Parse both agent modules and fail the build if an MQTT password is a string
  literal or a `config_value()` default.
- Verify that both agents stop before `connect_async()` when username or
  password provisioning is absent or empty.
- Provision two test-device identities and verify that each can access only its
  own serial topics; explicitly deny sibling serials and all `+`/`#` fleet
  filters.
- Verify that the control service can consume required fleet wildcards with a
  separate identity that is absent from field-agent artifacts.
- Rotate a test credential and confirm that the old value can no longer connect
  while the device resumes with the replacement.
- Deliver signed and unsigned high-impact command fixtures and verify that only
  an authorized, fresh command reaches `process_command()` or the Geotek worker.

## Summary

At the reviewed revision, two deployed agents embed the same masked MQTT
credential and use it as an operational fallback. We traced that value from
source, through Paho authentication and privileged subscriptions, into command
handlers capable of changing device, receiver, license, and stream state. The
offline PoC confirms the repeated hard-coded pattern without exposing the
secret or contacting any service.

Current exploitability still depends on broker reachability, credential
validity, and ACL scope. Those are important constraints, not reasons to retain
the design: a secret distributed to every source reader is no longer a secret,
and a field-agent identity should never span a fleet control boundary. The
durable fix is to rotate the exposed account, remove all fallback literals,
provision unique device identities, narrow broker ACLs, and add an independent
authorization layer for high-impact commands.
